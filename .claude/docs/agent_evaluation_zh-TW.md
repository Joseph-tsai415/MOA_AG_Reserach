# 研究 agent 評測手冊 — 準確度、穩定性、安全性覆蓋率

> **狀態：** 提案／大綱 · **撰寫日期：** 2026-08-25 · **範圍：** 如何「測試」這套 MOA-AG 研究 agent，
> 不是如何「執行」它。隨需查閱文件（不自動載入），性質同 `pipeline_changelog.md`。
> **英文版：** `.claude/docs/agent_evaluation.md`（本中文版另含 §2 出題者手冊與 §12 閱讀檢查清單）

---

## 0. 這份文件在量什麼

「這個 agent 好不好」這句話裡混了三件事。三件要分開量，**不可以平均**：

| 面向 | 問題 | 什麼情況量得到？ |
|---|---|---|
| **準確度** | 答案對不對？ | **只有**在「有標準答案」時 |
| **穩定性** | 同一題問五次，答案一不一樣？ | **永遠**量得到 |
| **流程合規** | 該跑的 gate 到底有沒有跑、有沒有過？ | 永遠，而且免費 |

一套系統可以**穩定地錯**，也可以**不穩定地對**。流程合規是另外兩項的先行指標：一次 run 少了
citation-grounding 的產出，不叫「應該還好」，叫**沒有被量過**。

還有第四件事，本專案目前沒有把它當一級指標：**安全性覆蓋率**（§9）。它會被放進上面的框架裡評分，
但它值得單獨拉出來當頭條數字 —— 因為現在它是**靠運氣產生的**。

## 1. 三種「真相狀態」— 對應 `research_questions.md` 的 Q1／Q2／Q3

`research_questions.md` 裡那三題不是三個主題，而是三種**知識論狀態**，每一種只能用不同方式評分。
這是整套評測的骨架。

| 層級 | 真相狀態 | 對應 | **可以**打什麼分 | **不可以**打什麼分 |
|---|---|---|---|---|
| **T1 — 密封標準答案** | 出題者知道答案，但不給 agent 看 | **Q1**（腸道免疫細胞分離：酵素 × 表位那些事實是已知的，且答案在出題者手上） | recall、捏造率、precision、信心校準 | — |
| **T2 — 前瞻性** | 方向已有預期，實驗還在跑 | **Q2**（小腸延長，對照已發表模型的量級） | 預先登錄的方向命中、區間覆蓋、Brier score —— **事後**才計分 | **現在**的絕對準確度 |
| **T3 — 開放假說** | 目前根本沒有答案 | **Q3 Arm B**、所有外泌體 cargo run、大多數 `results/` MOA run | 可追溯性、可否證性、**安全性覆蓋率**、內部一致性、決策實用性、穩定性 | **正確性** |

> **總則。** 絕對不要對 T3 的產出打「正確性」的分數。沒有東西可以對照，所以那個分數實際上是
> 「聽起來合不合理」的分數 —— 而**優化「聽起來合理」正是製造出一個自信滿滿的幻覺機器的方法**。
> 這跟 CLAUDE.md §3 已經寫進報告規則裡的原則是同一條（「一個真正新穎的橋接與一個幻覺，在文獻檢查
> 眼中長得一模一樣」），差別只在這次它管的是**評測者自己**。

T3 要量的是**決策實用性**：讀完之後，一個做實驗的人知不知道星期一該做什麼？什麼結果會讓這個想法直接死掉？

## 2. 出題者手冊 —— 你自己要先準備什麼 ★

這一節是給**出題的人**看的。評測的品質上限由題目決定，不是由 agent 決定；題目沒準備好，
後面所有數字都沒有意義。

### 2.1 每一題都要準備的六樣東西（不分題型）

| # | 要準備的東西 | 為什麼 |
|---|---|---|
| 1 | **逐字題目**（存檔，一字不改） | 每次微調措辭，量到的就是「題目的變異」而不是「系統的變異」。題目必須凍結。 |
| 2 | **題型分類（T1／T2／T3）** | 決定了這題可以打什麼分。分錯型 → 分數全部無效（例如把 T3 當 T1 打正確性）。 |
| 3 | **modality**（小分子／複方中藥／EV 生物製劑／基因擾動） | 決定安全危害清單套哪一份（§9）。 |
| 4 | **預期終局：該 PROCEED 還是該 HALT** | **最常被忘記準備的一項。** 一批題目裡至少 1/3 應該是「正確答案是拒絕作答」的題。 |
| 5 | **要不要附資料**（RNA-seq、配方組成、cargo 清單……） | 有附就要一起凍結版本與日期，否則下次重跑不可比。 |
| 6 | **執行條件**：model id、pipeline 版本、快取日期、live 還是 replay 模式 | 這四項不同的兩次 run，本來就不該互相比較。 |

### 2.2 T1 題（像 Q1）—— 你要準備一份「密封答案卷」

**準備原則**

- **事實要原子化**：一句話 = 一個可否證的事實。「Liberase TL 會切 CD8、部分切 CD19」是一個事實；
  「Liberase TL 對 flow panel 有影響」不是（含糊到怎樣都算對）。
- **每個事實都要有 PMID + 出處位置**（Abstract／Results／Fig. 2／Table 1）。出處位置很重要：
  數字若只在圖裡，agent 拿不到全文就抓不到，這是**覆蓋率問題不是捏造問題**，計分要分開。
- **標「必答／加分」**：必答題構成這一題的及格線。
- **標建立日期**：文獻會變，一年要複查一次。
- **必須密封**：放在**工作目錄之外**，或只把 hash commit 進 repo。放進 repo 裡 agent 讀得到，這題就作廢。
- **建議題量**：一題 15–30 個事實。

**★ 陷阱題（抓捏造最有效的一招）**
刻意放 2–3 個「文獻上其實根本沒人量過」的欄位，**正確答案是「未報導」**。
會照實寫「未報導」的系統，跟會補一個看起來合理的數字的系統，只有這種題分得出來。

**答案卷範本**

| id | 事實敘述 | 方向／數值 | PMID | 出處位置 | 必答？ | 建立日期 |
|---|---|---|---|---|---|---|
| Q1-07 | Liberase TL 切除小鼠腸道 CD8 表位 | 陽性率下降 | 12345678 | Fig. 2C | 必答 | 2026-08-25 |
| Q1-19 | 小腸 LP 嗜酸性球佔 CD45⁺ 比例（C57BL/6，8 週齡） | **未報導** | — | — | 陷阱 | 2026-08-25 |

### 2.3 T2 題（像 Q2）—— 你要準備一份「預先登錄書」

必須在**揭盲之前**寫完並加上 hash，否則不計分。

```
預測：      小腸長度差異的主要驅動層 = 外縱走肌 (longitudinal smooth muscle)
數值區間：  +5～10 cm（相對 WT，新鮮組織、固定張力下測量）
方向：      增長（非發炎性縮短）
判讀方式：  分層形態計量（mucosa／submucosa／inner circular／outer longitudinal）
判死條件：  若增長主要來自 mucosa 而肌層厚度無差異 → 本假說否證
登錄日期：  2026-08-25    hash: <sha256>
```

**你自己要先想清楚的一件事：什麼結果會讓你說「這個假說錯了」。**
想不出來，這題就還不能當測驗題 —— 因為之後不管出什麼結果你都會覺得「有講到」。

### 2.4 T3 題（像 Q3、外泌體）—— 你要準備「決策情境」與「隱藏檢查點」

沒有標準答案，所以你準備的不是答案，是**評分的依據**：

1. **寫下這份報告要幫你做什麼決定。** 例如：「決定下個月要不要花錢做 cargo 的 LC-MS／small-RNA-seq」。
   報告若沒有幫到這個決定，分數就低 —— 跟它寫得多漂亮無關。
2. **準備該 modality 的危害清單**（§9），當成安全性評分表。
3. **★ 準備 2–3 個「你已經知道應該被提到」的風險當隱藏檢查點。**
   例如 EV 產品的內毒素／無菌性、外用製劑的接觸性致敏。報告沒提到 → 覆蓋率扣分。
   **這是把「沒有標準答案的題目」變成可打分的關鍵技巧。**
4. **準備反駁任務**：另外開一個獨立的 agent，專門去駁這份報告的前三大主張，看幾條活下來。

### 2.5 出題品質自檢（出完題先問自己五句）

- 這題的答案，Google 第一頁就找得到嗎？→ 找得到就測不出東西（測到的是檢索，不是推理）。
- 這題有沒有可能「講得含糊就算對」？→ 有，就改成數值或方向。
- **我能不能在讀報告之前，就先寫下判定標準？** → 不能，代表這題還沒準備好。
- 同一題丟五次，我期待答案完全一樣嗎？→ T1 是；T3 只期待**決策**一樣（§5）。
- 這批題目裡，「正確答案是 HALT」的陰性對照有沒有佔到 1/3？

### 2.6 題目卡範本（每題一張，存進題庫）

```yaml
id:            NEG-03
tier:          T1
modality:      小分子
prompt:        "分析 caffeine 在 systemic sclerosis 的作用機轉"   # 逐字，不可修改
expect:        HALT            # 預期終局
answer_key:    sealed/NEG-03.md   (sha256: ...)   # 工作目錄之外
attached_data: 無
run_mode:      replay @ cache-2026-08-25
notes:         陰性對照 —— 交集應無法通過 overlap_p / z_c 門檻
```

## 3. 測驗題庫的組成

**T1 — 密封標準答案（建 8–10 題）**
- **Q1 型事實檢索**：答案在出題者手上，原子化、有 PMID、可否證。
- **回溯 MOA 題**：機轉已寫進教科書的「化合物 × 疾病」配對，盲跑 Step 0–5：
  tofacitinib × RA（JAK1/JAK3）、celecoxib × OA（PTGS2）、imatinib × CML（ABL1/KIT/PDGFRA）。
  已知的主要標的**必須**出現在 hub 集合裡。
- **陰性對照**：沒有合理關聯的配對，系統必須在 Step 3 **HALT**。
  **這是最重要的一類題：一套從不說「不」的系統，對任何東西都會生出一個陽性結果，等於沒有價值。**
- **已知缺陷重演**：session8（捏造引用、非人類標的）已經是
  `moa_lib/tests/validate_session8.py` 的 fixture，把它正式列為常駐迴歸題。

**T2 — 前瞻性（1–3 題，長期累積）**
- Q2／skin→gut 延長表型：在讀出結果之前先做預先登錄（§7）。

**T3 — 開放題（6–10 題）**
- Q3 Arm B growth-bridge、三個 EV cargo run、一個全新的複方 × 疾病。
- 每題跑 **×5** 量穩定性（§5），並用量表評分（§8）。

## 4. 分離「模型變異」與「世界變異」—— 錄放快取

兩次 run 不一樣，可能是**模型骰子不同**，也可能是**ChEMBL 更新了**。不分開就什麼都歸因不了。

- **Live 模式** —— 真的打 API。量的是端到端的真實狀況：資料庫漂移、限流、服務中斷。
  定期跑；這才是託管服務實際會遇到的情況。
- **Replay 模式** —— 所有 HTTP 回應都由凍結的快取供應，唯一會變的輸入只剩模型隨機性。
  **所有穩定性數字都必須來自 replay 模式。**

實作很小，因為每次 run 本來就已經把抓到的資料存進 `results/{run}/data/`：

- `moa_lib/eval/cache.py` —— 一個 `requests` 的 shim，鍵值為
  `(method, url, 排序後的 params, body-hash)` → 硬碟上的 JSON，支援 `record`／`replay`／`strict` 三種模式
  （`strict` 在快取未命中時直接失敗，避免偷偷打了一次 live 而污染 replay）。
- 每次 run 都要釘住並記錄：model id、pipeline 版本、快取日期、skill 版本、`MOA_RUN_DIR`。
  這幾項不同的兩次 run，本來就不可比。

## 5. 穩定性指標 —— 每題 replay 五次

依 pipeline 的層級分組，最重要的排最前面。門檻是「第一輪拿來校準用的起手值」，不是鐵律。

| 層級 | 指標 | 建議門檻 |
|---|---|---|
| **決策層** | 五次 run 的 HALT vs PROCEED 一致性 | **5/5** —— 未達即為 blocker |
| **決策層** | Bottom line 判定類別（值得推進／有潛力但未證實／還不行／否），Fleiss κ | κ ≥ 0.8 |
| **集合層** | hub 基因集合兩兩 Jaccard 平均（Step 3） | ≥ 0.80 |
| **集合層** | List A／List B Jaccard；前 10 名排序一致性（RBO） | ≥ 0.75／≥ 0.80 |
| **數值層** | \|A\|、\|B\|、\|A∩B\| 的變異係數 | ≤ 10 % |
| **數值層** | `z_c` 絕對全距；`log10(overlap_p)` 全距 | Δ ≤ 0.05 · ≤ 1 個數量級 |
| **主張層** | 機轉三元組 `(標的, 方向, 路徑)` 集合 Jaccard；**排名第一**的機轉是否同一個 | ≥ 0.7 · 5 次中 ≥ 4 次相同 |
| **引用層** | 參考文獻集合 Jaccard | ≥ 0.7 |
| **引用層** | 捏造引用數 | **每一次都必須是 0 —— 變異必須為零** |
| **安全層** | 危害覆蓋率在五次之間的分數全距（§9） | ≤ 1 分 |
| **成本層** | tokens · 時間 · 費用的變異係數 | ≤ 25 %（`Schollar_System` 是按 job 計費，這項有實際意義） |

**要報「實際的分歧」，不要只報係數。** N=5 的時候，「第 2 跟第 4 次掉了 STAT3」比
「Jaccard = 0.82」有用得多。

## 6. 準確度指標 —— 只適用 T1

**每個事實四種判定：**

| 判定 | 意思 | 權重 |
|---|---|---|
| **HIT** | 有寫、正確、引用也對 | +1 |
| **MISS** | 沒提到 | −1 |
| **CONTRADICTION** | 有寫但寫錯 | **−10** |
| **UNSUPPORTED** | 有寫，但引用的文獻並不支持這句話（捏造） | **−10** |

這個不對稱是刻意的，也是整套計分的核心：**漏掉一件事的代價是再查一次文獻；
編造一件事的代價是白做一個實驗。** 任何把兩者等同看待的指標，都會把系統推向「多說一點」。

衍生的頭條數字：
- **Recall** = HIT /（HIT + MISS）
- **捏造率** =（CONTRADICTION + UNSUPPORTED）／每 100 條主張 —— **這是頭號數字**
- **引用落地通過率** —— 自動，`moa_lib.citation_grounding`（**主張層級**，不是參考文獻層級；
  v11.2 changelog 記錄過：只查參考文獻層級曾讓一筆捏造過關）
- **數字忠實度** —— 自動，`moa_lib.lineage_audit` 的 FAIL 數
- **hub 標的 recall／precision**（回溯 MOA 題）—— 沿用 `moa_lib/benchmark_recall.py`。
  它當初被退出**報告章節**是對的（它比的是 pipeline 版本不是生物學）；但在**這裡**它正好是對的工具，
  因為評測要比的就是版本。
- **陰性對照特異度** = 應該 HALT 的題目中真的 HALT 的比例。單獨列頭條。
- **信心校準** —— 把每條主張依其標示的證據層級／GRADE 確定性分箱，畫出各箱的實際正確率，
  報 **expected calibration error** 與 reliability diagram。
  一套「Moderate」的主張只有 40 % 正確的系統，就算 recall 很高也是校準失敗 ——
  而**校準失敗才是讓報告變危險（而不只是不完整）的原因**。

## 7. T2 —— 前瞻性計分（Q2 那種情境）

對真正新穎的研究而言，這是唯一沒有偏誤的準確度訊號。它很慢，所以**現在就要開始**，
讓它跟著實驗室真正的實驗一起累積。

1. **預先登錄。** 揭盲前寫 `prereg.md`（範本見 §2.3），加 hash 並記錄在 run 資料夾裡。
   **沒有事前登錄的預測不計分。**
2. **讀出結果時計分：** 方向命中／未中 · 區間覆蓋（真值有沒有落在宣稱的區間內） ·
   機率型判斷用 **Brier score**。
3. **要公布失準。** 一次有預先登錄的前瞻性失準，價值高於十次回溯性命中 ——
   它是唯一能校準 §6 那些信心分箱、且適用於新穎生物學的東西。

## 8. T3 —— 沒有標準答案時的評分量表

由**獨立的**評審評分 —— 用本量表驅動 `report-qa` agent，**絕不可以**由寫報告的那個 session
自己打分 —— 另加約 20 % 抽樣的人工複核。

五個面向，各 0–3 分：

1. **可追溯性／可解釋性** —— 每個頭條數字與機轉主張，能不能靠重跑 `scripts/` 從 `data/` 重建？
   （大部分可自動化 —— 就是 `lineage_audit` 加上資料夾稽核。）
   讀者能不能在不信任作者的前提下，跟著 cargo／化合物 → 標的 → 路徑 → 表型走完一遍？
2. **可否證性** —— 未量測的主張中，附上**assay + 讀出 + 判死條件**的比例。
   CLAUDE.md 的 Step 4/5 已經強制要求，這裡量的是「到底有沒有做到」。
3. **安全性與責任風險覆蓋率** —— 用 §9 的 modality 危害清單。
4. **內部一致性** —— Bottom line、表格、Limitations 三者不打架；conflict log **不是空的**
   （方向性檢查若零衝突，依定義就是壞的）；被 gate 掉的集合沒有漏進計分表格。
5. **決策實用性** —— 有沒有指名**最便宜且具決定性**的實驗，而且它真的最便宜、真的有決定性？

再加一項**對抗性探測**：另開一個獨立 agent，任務是**駁倒**報告的前三大主張，計分＝活下來幾條。
這是 T3 用來替代標準答案的東西，也是唯一便宜、又真的能分辨「新穎橋接」與「自信編造」的儀器。

## 9. 安全性檢查的量法 —— 以及外泌體的實測結果 ★

**實測狀態（2026-08-25），同一個 modality（EV 生物製劑 × 異位性皮膚炎）的三次 run：**

| 危害類別 | `adsc_exosome…` | `…_session2` | `hamsc_haesc_exosome…` |
|---|---|---|---|
| 反治療方向 | 只有一行纖維化的 kill criterion | **血管新生 —— 進頭條、且有專屬實驗** | 只有 TNFAIP3 的標的層衝突 |
| 產品／藥物交互作用 | — | **GAS5 × 外用類固醇，另配實驗 7** | — |
| 鑑定與批次特性 | — | **MISEV／NTA／CD63-Alix-TSG101** | — |
| 無菌性 · 內毒素 · 免疫原性 · 致瘤性 | 0 | 0 | 0 |

Session 2 表現確實好 —— 它抓到了一個「任何療效指標都不會顯示出來」的藥物交互作用風險。
但它的兄弟 run 沒有抓到，而且**三次 run 沒有任何一次處理 EV 的產品品質類危害**。

原因是**結構性的，不是誰疏忽**：**Step 5 的報告模板裡根本沒有安全性章節**
（假說 · MOA 表 · 應用情境 · 驗證實驗 · 限制 · 參考文獻）。
安全性只有在「生物學剛好逼著方向性／衝突 gate 把它擠出來」時才會出現。

所以「這份外泌體 review 有沒有做安全性檢查」的誠實答案是：
**有時候有，靠運氣，而且只在標的層級 —— 而這個變異本身就是一項可量測的不穩定性。**

**評分工具。** 依 modality 選一份危害清單，逐項打分：
**2 分** = 有處理且配了具名實驗 · **1 分** = 只提到 · **0 分** = 完全沒有。
`安全性覆蓋率 = 實得 / 適用總分`。

- **通用** —— 反治療方向 · 標的本身的責任風險 · 脫靶／泛活性 · 藥物或產品交互作用 ·
  族群禁忌 · 給藥途徑與暴露現實性。
- **EV／細胞衍生生物製劑** —— 供體與批次變異、鑑定（MISEV） · 無菌性、內毒素、黴漿菌 ·
  免疫原性 · 促增生／致瘤性 cargo · 促血管新生 cargo · 生體分布／異位遞送 ·
  法規分類（ATMP／HCT-P）。
- **小分子與中藥複方** —— PAINS／frequent-hitter 假陽性 · 中草藥肝損傷（HILI） ·
  CYP／UGT 交互作用 · 外用製劑的接觸性致敏與光毒性 · 摻偽與重金屬 · 孕婦／兒童排除。
- **基因擾動（Q3 型）** —— 組織限定性的干擾（病灶真的只在局部嗎） · KO 的脫靶效應 ·
  生長 vs 腫瘤化。

**建議 —— 把這件事從「評測項目」升級成「pipeline 的一部分」。**
在 Step 5 加一節《責任風險與安全性問題》，並新增 `moa_lib/safety_checklist.py`
（modality → 危害清單 → 覆蓋率分數，寫進 `step5_confidence_dashboard.md`）。
這樣這個指標量的就是**合規**而不是運氣，評測的工作也縮小成「確認它有跑」。
這屬於方法學變更 → 要在 `pipeline_changelog.md` 加一列（v11.3）。

## 10. 流程合規 —— 免費、全自動、每份交付物都跑

只看資料夾就能機器檢查，完全不需要模型介入。

- **必要產出是否齊全**（依 CLAUDE.md §8）。*目前基線（19 份交付物）：*
  只有 **4 份**有 `report_qa_review.md`；`adsc_exosome_atopic_dermatitis_session2` 沒有，
  但它的前一版有；6 個 `results/` run 兩份（QA 與 `data_integrity_check.md`）都沒有。
- **gate 有執行的證據** —— provenance 判定存在 · 特異性數字存在（`overlap_p`、`z_c`、decoy） ·
  citation-grounding 產出存在 · lineage audit = PASS · QA 判定 = SHIP。
- **報告語氣違規** —— 在報告本文 grep 版本標籤／模組名稱（CLAUDE.md §5）。
- **圖表完整性** —— 分類要有圖例、連續色階要有 colorbar、`bbox_inches='tight'`、
  PNG 讀回來檢查豆腐字（glyph gate）。

把這套接進 `Schollar_System` 當作 run 完之後的檢查，讓**每一個正式 job** 都被評分，不只是評測題。
這仍在服務層的界線之內：它只檢查與分類產出，不計算也不詮釋任何科學結果。

## 11. 記分卡與放行規則

每一輪評測產出一頁：

| 頭條指標 | 出處 | 建議門檻 |
|---|---|---|
| 決策可重現性（HALT/PROCEED、判定 κ） | §5 | 5/5 且 κ ≥ 0.8 |
| 每 100 條主張的捏造率 | §6 | **0** |
| 陰性對照特異度 | §6 | 100 % HALT |
| T1 recall | §6 | 只看趨勢，不設絕對門檻 |
| 校準誤差 | §6 | ≤ 0.15 |
| 安全性覆蓋率 | §9 | ≥ 適用項目的 0.8 |
| 流程合規 | §10 | 100 % |

**放行規則。** pipeline 版本要升版，必須所有設門檻的頭條指標都達標，且在凍結題庫上**沒有任何一項
比前一版退步**。
**迴歸規則。** 只要動到 CLAUDE.md §3 或 `moa_lib/`，就重跑題庫；出現退步就擋下這次變更，
若仍決定接受，必須在 changelog 自成一列說明這個取捨換到了什麼。

## 12. 讀報告時你要看什麼 —— 10 分鐘檢查清單 ★

依「最容易出事」排序。這份清單也適合直接拿給不熟這套系統的同事用。

| # | 看哪裡 | 出問題長什麼樣 |
|---|---|---|
| 1 | **Bottom line 對照 Limitations** | 開頭說「值得推進」、限制卻說「療效未證實」→ 內部打架 |
| 2 | **隨機抽 3 個數字回 `data/` 對** | 表格列數 ≠ 標題宣稱的數量（就是 Session-9「81 筆掛在 14 hub 標題下」那種漏洩） |
| 3 | **隨機抽 3 條引用，打開 PMID 看摘要** | 看的是「摘要有沒有支持**那一句話**」，不是「有沒有這篇論文」。真論文被用來撐它沒說過的話，就是幻覺 |
| 4 | **conflict log 是不是空的** | 空的＝方向性檢查壞了。一次「每個標的都剛好有利於治療」的分析是循環論證 |
| 5 | **該 HALT 的有沒有 HALT** | `overlap_p > 0.05` 或 `z_c > −0.15` 卻繼續往下寫 |
| 6 | **每個「未量測」的主張有沒有配 assay + 判死條件** | 只留一句「方向未定」＝把該做的工作丟給讀者 |
| 7 | **安全危害清單覆蓋率**（§9） | EV 產品卻整份沒有內毒素／無菌性／致瘤性 —— 這正是目前的實測狀況 |
| 8 | **hub 表裡有沒有混進被 gate 掉的基因** | 原始交集與計分後集合共用同一個容器 |
| 9 | **途徑／暴露是否與 Step 0 一致** | 外用製劑卻寫全身性的收案族群、血漿親和力、全身用藥比較品 |
| 10 | **方法註腳的 pipeline 版本與 session 編號** | 沒有這一行，兩份結論相反的報告就只是「無法解釋的矛盾」 |

## 13. 評測本身的風險

- **污染。** agent 可能在更早的 session 看過答案卷，或答案卷就放在它讀得到的 repo 裡。
  答案卷要放在工作目錄之外，只 commit hash，並定期換題。
- **評分者偏誤。** QA agent 跟作者共用同一個模型。**絕不可以讓寫報告的 session 自己打分**；
  抽樣人工複核，可能的話用**不同的模型**評分。
- **標準答案會腐壞。** 所謂「已確立」的事實會變。每份答案卷都要標日期，每年複查。
- **Goodhart 定律。** 只要開始優化 hub recall，系統就會把 List A 放寬。
  **每一個 recall 指標都必須配一個 precision／捏造率**，讓「放寬」會被扣分。**永遠不要單獨公布 recall。**
- **N 太小。** 五次 replay 只給得出粗估。每個彙總統計旁邊都要附上原始的分歧內容。
- **評測不是科學本身。** 這套量的是 agent 可不可靠，不是假說對不對。
  對新穎研究而言，只有 §7 碰得到真相。

## 14. 最小起步

依相依順序，每項大約一個工作 session：

1. **`moa_lib/eval/compliance.py`** —— §10 的資料夾／gate 稽核，跑遍現有 19 份交付物。
   零模型呼叫、立刻得到基線，而且可以回溯評分已經做完的工作。
2. **`moa_lib/eval/safety_checklist.py`** —— §9 的危害清單；回溯評分三個 EV run
   與最近兩個 MOA run。**直接用數字回答外泌體那個問題。**
3. **`moa_lib/eval/cache.py`** —— 錄放 shim（§4）。沒有它，任何穩定性數字都無法歸因。
4. **題庫** —— 3 題陰性對照 + 3 題回溯 MOA + session8 迴歸題；每題 replay ×5，
   產出 §5 的穩定性記分卡。
5. **`prereg.md`** —— 為正在進行的 Q2 延長表型讀出做預先登錄（§7）。現在做很便宜，**事後補不回來**。

**產出放哪裡。** 一輪評測是 `reviews/` 形狀的交付物，不是 MOA run：
`reviews/agent_eval_{YYYY-MM-DD}/`，含 `data/`（各次 run 的原始指標）、`scripts/`（編號、可重跑）、
`figures/`、報告本體，以及它自己的 `report_qa_review.md`。
**評測者要接受與它所評分的對象同等的證據要求** —— 否則它就正好是 v11.2 當初要修掉的那種
「只有 `.md` + `.pdf`、無法稽核也無法重現」的東西。
